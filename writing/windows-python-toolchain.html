Windows 上把 Python 工具链调到顺手

编码、路径、链接、文件锁——四个坑占了我在 Windows 上遇到问题的一大半。这篇是踩完之后整理的操作清单。

  • 发布 2026-09-08
  • 阅读 约 7 分钟
  • 标签 Windows · Python · 环境

一、编码：先 chcp 65001

cmd 默认代码页是 GBK，中文输出一旦进了管道或者被重定向，就会变成乱码或者直接抛 UnicodeEncodeError。批处理开头固定两行：

chcp 65001 >nul
set PYTHONIOENCODING=utf-8

PowerShell 要设两个东西，只设一个不管用：

$OutputEncoding = [Console]::OutputEncoding = [Text.UTF8Encoding]::new()

写文件时统一显式声明，别依赖平台默认值：

open(path, "w", encoding="utf-8", newline="\n")

少了 newline="\n"，CSV 在 Excel 里打开会多出空行——这个坑我踩过两次，第二次才发现是换行符被写成了 CRLF。

二、路径：两种写法别混用

Git Bash / MSYS 认 /d/repo，Python 和绝大多数原生程序认 D:/repo。把 MSYS 风格路径传给 python，轻则找不到文件，重则被当成相对路径解析到别的地方。

  • 在 bash 里调 python，路径写 D:/repo，或者先 cygpath -w 转一次。
  • 工具的 workdir 参数同理：D:/repo 可以，/tmp 不行——那是 MSYS 的虚拟根，不是真实目录。
  • 脚本内部拼路径用 pathlib.Path，别手写反斜杠，反斜杠在字符串里是转义符，迟早出错。

三、链接：junction 比 symlink 省事

需要把某个目录挂到另一个位置时，用 junction：

mklink /J D:\link D:\target

它不需要管理员权限，Python、Node、资源管理器都当普通目录对待，跨盘也能用。符号链接（/D）则要开发者模式或提权，很多工具对它的识别还不一致。

删 junction 用 rmdir D:\link，不要用会递归跟随的删除工具。跟进去删，删掉的是目标目录里的真实文件。

四、文件锁：WinError 32

[WinError 32] 另一个程序正在使用此文件，进程无法访问——九成情况是某个后台 python 或 node 进程还占着这个目录，最典型的是上一次没关掉的本地 HTTP 服务。

排查顺序：先看端口有没有人占，再顺着 PID 找进程。

netstat -ano | findstr :8142
taskkill /PID 40844 /F

除了自己的进程，还有三个常见的隐形占用者：资源管理器的预览窗格、杀毒软件的实时扫描、OneDrive 的同步。遇到删不掉又找不到进程的情况，先关预览窗格。

养成一个习惯：本地服务固定端口，起服务前先探一次端口，被占就直接报错，而不是让服务静默起在别的端口上——那会导致你以为在测新版本，其实在测旧的。

五、还有两条容易忽略的

  • 长路径：默认 260 字符限制会在 node_modules 或者深层缓存目录里炸掉。开 LongPathsEnabled=1，或者把工作区放在盘符根下浅一层。
  • 换行：core.autocrlf=false 配合 .gitattributes 里的 * text=auto eol=lf，可以省掉那种「只改了一个字却整个文件都是 diff」的提交。

现在的日常

最终形态很朴素：一个 .bat 起本地服务（chcp + 固定端口 + 前台报错），一个 .bat 起隧道，脚本内部全部绝对路径 D:/，所有输出 UTF-8。踩过的坑没有消失，只是变成了模板里的两行。
