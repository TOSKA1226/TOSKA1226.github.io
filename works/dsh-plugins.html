dsh 插件工具箱

把 Blender 建模、Office 文档、浏览器自动化收进一张可枚举、可授权的工具面。

  • 分类 Python
  • 角色 架构 + 实现
  • 规模 34 family / 228 op
  • 状态 持续维护

背景与目标

模型要真干活，就得能操作外部软件：Blender 建模、Word / Excel / PPT、浏览器里的页面。每个软件一套 API、一套错误处理，如果原样暴露给模型，结果是它记不住参数，也说不清自己有没有权限。

目标是把三件事分开：能做哪些事收敛成一张可枚举的表，能不能做变成显式授权，要做很久变成可查询的作业。

我具体做了什么

  1. 工具面按「家族 + 算子」分层现在是 34 个家族、228 个算子。只读算子（审计、量测、清单、导出检查）不需要打开 GUI 会话；写算子（改场景、跑渲染）必须先拿到写授权。模型看到的是算子目录，而不是一堆零散函数。
  2. 长任务全部进队列队列上限 pending 64、GPU 1、CPU 2。submit 立刻返回 jobId，之后用 status / wait / collect / cancel 跟进。渲染和后台脚本分开排，GPU 只有一个槽，避免两个渲染互相拖死。
  3. 写权限做成 scopeexclusive / collection / prefix / object 四档，可以授权到对象级。给小范围授权，模型改不到范围外的东西；人类暂停时，agent 的任何写调用直接返回 human_action_required，而不是静默排队等恢复。
  4. Office 与浏览器接在同一套出口docx / xlsx / pptx 的读取、写入、校验走同一批工具；浏览器用 CDP 驱动，截图、取 DOM、点按都能被脚本化，不需要另开一个「浏览器专用」入口。

为什么是排队而不是并发

一个 GPU 两个 CPU 槽，看着保守，实际是把「任务失败」换成「任务等待」。之前并发跑两个渲染，两个都超时；现在第二个排队，第一个正常出图。

关键取舍

维度选了原因
执行面GUI 优先，headless 备用取一帧不值得启动新进程
权限默认无写权限宁可多一步显式授权
任务队列而非并发资源有限，失败比等待贵
接口算子目录而非自由脚本模型能枚举，才能自己纠错

结果

  • 34 个家族、228 个算子可枚举，只读操作用一次目录查询就能发现；
  • 重活不再卡对话：超过约 1 秒的调用转后台作业，返回 jobId；
  • 写操作有授权记录，人类暂停时立即失效；
  • Office 与浏览器的产物落在同一套输出约定里。

下一步

想把作业结果统一成一个 schema（产物路径、耗时、日志尾部、失败原因），上层就不用为每个算子单独写解析。另外截图 diff 还没做，视觉验收目前仍靠人眼看图。
